# Static architecture rules

`pnpm check` is the one read-only command for port code. It runs these steps concurrently: Oxfmt in check mode, type-aware Oxlint, a lint and format coverage check, official `tsc` 7.0.2 per program with inspection of the program's files, and a dependency-cruiser graph from shipped entries. It also scans lint escapes and validates manifests. It exits nonzero on any finding, including a failing tool whose output it cannot read. It never writes: `tsc` runs with `--noEmit --incremental false --composite false` whatever a tsconfig says, and the fixtures prove each run leaves the tree unchanged. `pnpm format` applies Oxfmt first and then runs the same checks. `pnpm check:fixtures` proves every rule below against disposable fixtures.

The build tier runs `pnpm check:bundles` after the desktop and offline player builds. It checks four runnable outputs and their bundler module inventories against allowed first-party sources and externals. The renderer and offline player must bundle all dependencies. The sandboxed preload may import Electron. Main may import Electron and Node builtins. Each desktop process has a separate TypeScript program for its source entry.

After packaging, `pnpm check:bundles --packaged` also requires the CLI, stdio MCP server, headless project host and update activation helper. Each inventory must include its source entry. The two clients reach the service through its client contract. Importing its storage writer or the SQLite builtin fails the check. The activation helper may use Node builtins and first-party updater code. The install rehearsal checks activation and rollback on disk.

The policy lives in [policy.ts](policy.ts). Scoped graph exceptions live in [exceptions.json](exceptions.json).

For Electron, the bundle check parses the first-party sources listed by the main and preload builds. It checks the literal preferences on direct `BrowserWindow` construction, including named import aliases. Each window must enable sandboxing, context isolation and web security and disable Node integration. The preload must expose a single `window.workshop` object with the reviewed function names in [desktop-contract.ts](desktop-contract.ts). The staged desktop QA exercises the bridge in a real window.

Electron 46.0.0-alpha.13 publishes one declaration file for main and renderer. The Node-only main and preload tsconfigs use `skipLibCheck` for ordinary builds. The static check turns declaration checking back on. Its exception matches only TS2304 for `VideoFrame`, `HTMLElement`, `HTMLElementEventMap` and `EventListenerOrEventListenerObject` in Electron's own declaration file. The same error in a first-party declaration fails the gate. Remove the exception when the upstream declarations pass with Node types alone.

The player exports a stylesheet alongside its TypeScript entry. Both the desktop renderer and offline player must include that stylesheet in their built module inventories. Removing it from either inventory fails `pnpm check:bundles`.

With the desktop and client programs present at `c46df48`, a clean-tree static pass through all checks took 10.4 seconds under concurrent load and reported six integration findings. The separate fixture run took 191 seconds for 61 scenarios and 118 read-only checker invocations. Three additional syntax probes caught a disabled window sandbox, spread overrides and an unexpected preload method without launching Electron.

## Coverage

- **Format and lint** cover every file outside the `legacy` list in `vite.config.ts`. That list names the frozen web workshop (`character-view`, `scripts`, `examples`, `docs`, `dist`) and `verification/baseline`. Remove an entry when its family moves into `packages/` or `apps/`.
- **Types and graph** cover the projects listed in `policy.ts`:
  - Required now: `packages/document`, `verification/protocol` and `tools/static`.
  - Planned: `character`, `player`, `workshop`, `hosts`, `desktop`, `cli`, `mcp` and the web player. Each is checked as soon as its directory exists.
- **Sources:** every `.ts`/`.js` file under a policy project must be loaded by one of its tsconfig programs, selected by Oxlint (so no `.gitignore`, Git exclude or ignore pattern hides it from lint and format), and free of package-local lint, format or ignore configuration.
- **Packages:** a workspace package without a policy entry fails. So does a missing required project.
- **Entries:** for a workspace package these are its `exports`, `bin` and `main` targets. Policy `entries` add any others.
- **Empty graph:** a project without entries fails, as does an entry missing from the graph. An empty graph never passes.

The parser is `@swc/core` because TypeScript 7.0.2 exposes no compiler API to dependency-cruiser 18.9, which needs either TypeScript below 7 or 7.1 or later. `tsc` 7.0.2 remains the only type checker. Switch the parser to `typescript` once a 7.1 pin is selected.

Type-aware lint runs oxlint-tsgolint 7.0.2007, which embeds its own TypeScript 7.0 build to compute types for lint rules. `typeCheck` stays off, so lint reports no compiler diagnostics; `tsc` 7.0.2 remains the only type checker.

The checker reads each effective TypeScript configuration before compiling. The checked programs accept an explicit list of compiler options, use the standard libraries bundled with TypeScript, and reject package import maps that could resolve differently at runtime. Root dependencies are listed separately from the allowed dependencies of each package.

### Limits

- Type-aware rules see types only in files a tsconfig program includes. The coverage rule therefore requires every project source to sit in a program.
- Contextually typed callbacks and function aliases can hide `any`. External input needs runtime schema validation. Code that narrows `unknown` correctly can still read a global at run time, for example `Reflect.get(globalThis, "process")` checked with a type guard. The document's runtime gate (`protocol`) and the bundle probes (G4b) cover what reaches a shipped bundle.
- Format coverage follows lint coverage, because Oxfmt walks with the same ignore files. The `fmt.ignorePatterns` list in `vite.config.ts` is reviewed with that file.
- The ambient scan reads top-level declarations of first-party modules in pure programs. Ambient declarations in dependencies stay under `skipLibCheck` where policy records it.
- The effect allowlist is path-based. The root `effect` module re-exports services such as `ConfigProvider.fromEnv` that read host state when run, so the static rule bounds imports and the runtime gate bounds behaviour.

## Behavioral rules and their runtime gates

These need execution, so the static check does not claim them.

| Claim                                                                                                                    | Gate                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| One accepted request has one effect; stale, duplicate, cancelled and conflicting requests are rejected; undo is exact    | `protocol` (G1, `verification/protocol`)                                                                  |
| Saved revisions survive a crash and recover                                                                              | `persist` (G2)                                                                                            |
| Messages reach paired conversations and clients                                                                          | `clients` / `steer` (G2–G3)                                                                               |
| Rendering and pixel fidelity                                                                                             | `render` (G4b)                                                                                            |
| Bundle inputs and externals for the player, renderer and restricted preload; the exposed preload API and window settings | Bundle probes in `policy.ts`, added with each bundle (G4b), and the packaged-app check (G5)               |
| Installed app, updates and rollback                                                                                      | `package` / `updates` (G5)                                                                                |
| Zero reachable legacy runtime JS                                                                                         | G5 runs `pnpm check` over every real entry. By then the `legacy` list is empty and every app is in policy |

## Timing

Measured on 2026-11-25 on the Windows gaming PC with Node 26.13.1 and pnpm 12.23.0, in a fresh worktree of the G1 tree (document, protocol and tooling: 29 linted files and roughly 240–395 files per tsc program). Before/after compares commit `f991ae0` with these repairs on the same tree.

The tools keep no caches between runs, so cold and warm times match. Steps run concurrently: format about 0.56 s, type-aware lint 1.13 s (0.62 s alone), coverage 0.71 s, types 1.28 s, graph 0.36 s. The repairs add about 0.1 s in-process and 0.05 s wall to the edit loop.

The desktop workspace run on 2026-11-26 checked 178 project sources in 13.5 seconds while the fixture and GPU suites were also running. The on-demand architecture fixtures took 196 seconds for 63 scenarios and 121 read-only runs. These include a valid transitive workspace dependency and an undeclared direct import of the same package.
